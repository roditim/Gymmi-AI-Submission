# Gymmi — תוכנית אימונים והתקדמות

[פתח את האפליקציה הציבורית](https://roditim.github.io/Gymmi-AI-Submission/app/) · [English presentation](https://roditim.github.io/Gymmi-AI-Submission/)

Gymmi הוא MVP למתאמן שרוצה לארגן אימונים בשבוע ולראות מה השלים. עוזר AI מפרש זמינות בשפה חופשית ומציע תאריכים וטווחי שעות לאימונים שכבר הוגדרו, לבדיקה ואישור לפני שמירה. לפי הבהרת המרצה שהועברה ב־4.11.2026, פריסה ל־Production עם קישור ציבורי היא חובה; CrewAI הוא המלצה ומודל ML מאומן אינו חובה. ההבהרה הזו מנחה את גרסת ההגשה.

## מה עושים באפליקציה

1. בוחרים שבוע ומוסיפים אימון: שם, תאריך, משך מתוכנן ותרגילים מתוך התוכנית האישית.
2. אפשר להתחיל משלושה אימונים לדוגמה ולערוך אותם.
3. אחרי אימון מסמנים הושלם או דילגתי. אפשר לבטל סימון ולתקן פרטים.
4. רואים כמה אימונים הושלמו ואת היסטוריית האימונים. כל השלמה שווה 100 EXP וכל 500 EXP מעלים רמה.
5. הכפתור ״עזרה בשיבוץ עם AI״ פותח חלון עם הצעה לתאריך ושעות. חשבון Google מחובר מאפשר לבדוק שעות תפוסות ביומן הראשי לפני ההצעה ושוב לפני השמירה.
6. מתחברים לחשבון כדי לשמור בענן ולטעון את היומן גם ממכשיר אחר. אפשר גם להוריד ולשחזר גיבוי JSON.
7. פותחים ״יומן חודשי״, בוחרים יום ומוסיפים או עורכים אימון. ניתן לפתוח טיוטת אירוע ב־Google Calendar או להוריד את האימונים המתוכננים בחודש כ־ICS לייבוא ידני. כפתור חיבור נפרד מיועד לסנכרון אוטומטי עם יומן Gymmi ב־Google, וממתין להגדרת OAuth של האפליקציה. אימון עם שעה מסונכרן כאירוע מתוזמן ואימון ללא שעה כאירוע יום שלם. ראו [הסבר היומן](docs/CALENDAR_HE.md).

בביקור הראשון נפתח חלון הדרכה עם דוגמאות מונפשות לאימון, שיבוץ AI, צבירת EXP והתאמת מאמן. אפשר לדלג או לפתוח אותו שוב דרך ״איך מתחילים?״. ״אימון חדש״ זמין בראש המסך; במובייל יש ניווט תחתון, וחשבון ו־AI נפתחים לפי הצורך. ראו [מדריך חוויית השימוש](docs/UX_HE.md).

העיצוב המעודכן מבוסס על סקירת מסכים של Hevy, Fitbod ו־Freeletics: כרטיס לאימון הבא, רצועת ימים, טבעת התקדמות ועריכה בחלונות ממוקדים. ראו [מקורות ושיקולי עיצוב](docs/UI_RESEARCH_HE.md). הפונט העברי Heebo נשמר מקומית עם רישיון; לא מועתקים נכסים מהאפליקציות האחרות.

במצב אורח הנתונים נשמרים ב־localStorage בדפדפן. בחשבון מחובר הם נשמרים בפרויקט Supabase נפרד בשם Gymmi, בארגון שאומת במסלול Free. כל משתמש יכול לגשת רק ליומן שלו. לרענון מידע ממכשיר אחר לוחצים ״טען מחדש מהענן״; אין עדכון חי אוטומטי. היומן המקומי אינו מועלה אוטומטית ונשאר זמין אחרי יציאה מהחשבון.

**הגדרת ה־MVP:** לבקשת המשתמש ובאישורו המפורש מ־4.11.2026, ההרשמה אינה דורשת אישור מייל ומכניסה מיד לחשבון. כתובת המייל משמשת לזיהוי אך הבעלות עליה אינה מאומתת. אין כרגע שחזור סיסמה באתר ואין ספק SMTP. בדיקת הרשמה ציבורית דרך הטופס נפרדת מבדיקות הענן הוותיקות שהשתמשו בחשבונות QA שאומתו בניהול. חשבונות הבדיקה נמחקים בסיום. ראו [הסבר על המימוש](docs/PROJECT_EXPLAINED_HE.md).

תוכנית הדוגמה היא תבנית לארגון, ולא תוכנית שנבנתה באמצעות AI או הותאמה רפואית. אין להזין מידע רפואי רגיש ביומן הלימודי.

במסך ״רמות ודירוג שבועי״ אפשר להצטרף בחשבון מחובר באמצעות כינוי, ולעזוב בכל רגע. הטבלה מציגה את 20 המובילים לפי תאריכי האימונים שהושלמו בשבוע הנוכחי לפי שעון ישראל. הניקוד מבוסס על דיווח עצמי. מסך התוכנית והיומן החודשי סופרים את אותן השלמות.

## קוד שאפשר להסביר

הקישור ״מאמנים״ פותח ספרייה ציבורית עם פרופילים שמאמנים מפרסמים בעצמם. משתמש מחובר יכול לפרסם פרופיל עם מייל עסקי, לתת דירוג מ־1 עד 5 למאמן אחר ולבקש התאמה באמצעות שאלון. הפונקציה `coach-match` מסננת לפי מטרת אימון, קהל ופורמט. OpenAI מקבל רק תגיות מובנות וציונים מצטברים של המועמדים ומחזיר עד שלוש הצעות. הפרופילים והדירוגים הם דיווחי משתמשים. יצירת הקשר פותחת טיוטת מייל אצל המשתמש.

| קובץ | אחריות |
|---|---|
| docs/app/index.html | מסכי האפליקציה והטפסים |
| docs/app/style.css | עיצוב והתאמה לטלפון |
| docs/app/app.js | שמירה, אימות נתונים, עריכה, סימון השלמה וחישוב התקדמות |
| docs/app/ai.js | בקשת הצעה, בדיקת הפלט ואישור מפורש לפני שמירה |
| docs/app/ux.js | הדרכה ראשונה, קיצורי דרך ומידע על הפעולה הבאה |
| docs/app/league.js | חישוב EXP ורמות והצטרפות לדירוג |
| docs/app/calendar.js, calendar-lib.js | תצוגת חודש, בחירת יום והוספה ידנית לקלנדר |
| docs/app/coaches/ | ספריית מאמנים, פרופילים, דירוג ושאלון התאמה |
| supabase/functions/coach-match/ | בחירת מועמדים, קריאה ל־AI ובדיקת ההמלצות |
| supabase/functions/ai-week-plan/ | פונקציית שרת: אימות משתמש, מכסה, קריאת המודל ובדיקת ההצעה |
| docs/app/cloud.js | טעינה ושמירה ב־Supabase עם בדיקת גרסה |
| docs/app/config.js | כתובת הפרויקט ומפתח publishable ציבורי בלבד |
| supabase/migrations/ | הגדרת טבלה והרשאות RLS |
| tests/browser_mvp.cjs | בדיקות משתמש בדפדפן |
| tests/cloud_mvp.cjs | בדיקות ענן ובידוד חשבונות מול שירות אמיתי |

זו אפליקציה עם HTML, CSS ו־JavaScript פשוטים, ללא framework או שלב build. GitHub Pages מגיש את הממשק ב־HTTPS ו־Supabase מספק Auth ומסד Postgres. SDK רשמי בגרסה קבועה נמצא ב־docs/app/vendor עם רישיון ופרטי מקור. עוזר השיבוץ קורא ל־OpenAI Responses API דרך Supabase Edge Function. המפתח נשמר ב־Supabase Secrets ולא בקוד הדפדפן. אין מודל חיזוי מאומן במוצר ואין יצירת תרגילים. ראו [איך עובד ה־AI](docs/AI_PLANNER_HE.md).

## הרצה מקומית

אפשר לפתוח docs/app/index.html, אך מומלץ שרת מקומי כדי לקבל סביבת דפדפן עקבית:

```powershell
python -m http.server 8520 --directory docs/app
```

פותחים http://localhost:8520. האפליקציה נטענת ישירות מהקבצים בתיקייה.

## בדיקות

תוצאות בדיקות מצב האורח נמצאות ב־verification/production-mvp-check.json, בדיקות הענן ב־verification/supabase-cloud-check.json ובדיקות ההרשמה ב־verification/signup-check.json. הדוחות מתעדים את הגרסאות שנבדקו ואת תרחישי הבדיקה.

לבדיקות דפדפן אופציונליות בסביבת פיתוח:

```powershell
npm install --no-save playwright
npx playwright install chromium
node tests/browser_mvp.cjs http://localhost:8520/
```

לא נדרשים npm או Python כדי להשתמש באפליקציה הציבורית. בדיקות היישום אינן רצות אוטומטית ב־GitHub Actions; לחיבור הפרסום אין הרשאת workflow.

## נתוני האפליקציה

בקשת שיבוץ שולחת ל־OpenAI את הזמינות שהמשתמש הזין ואת השמות והמשך של האימונים הרלוונטיים. בחיבור Google נשלחות גם שעות תפוסות מהיומן הראשי, בלי שמות אירועים. פרטי תרגילים, מייל והיסטוריית השלמות נשארים מחוץ לבקשה.

## Git והגשה

הריפו הציבורי התחיל בייצוא של עבודה מוקדמת. היסטוריית הקומיטים סוננה לקראת ההגשה כדי לכלול את קוד המוצר ואת המצגת הציבורית. הפיתוח נעשה בענפים וב־Pull Requests, בסיוע עוזר קוד. מחקר ה־ML המוקדם על ביקורים שבועיים נשמר בארכיון פרטי נפרד.

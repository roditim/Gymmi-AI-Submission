# Gymmi — תוכנית אימונים והתקדמות

[פתח את האפליקציה הציבורית](https://roditim.github.io/Gymmi-AI-Submission/app/) · [English presentation](https://roditim.github.io/Gymmi-AI-Submission/) · מדריך חזרה להצגה בעיצוב החדש

מדריך מלא להצגה: האפליקציה, הקוד, AI, Supabase, Git והיומן — כולל תסריט הדגמה ומושגים בפשטות; הערות בעברית לכל אחת מעשר השקופיות ב־private presentation notes.

Gymmi הוא MVP למתאמן שרוצה לארגן אימונים בשבוע ולראות מה השלים. עוזר AI מפרש זמינות בשפה חופשית ומציע תאריכים לאימונים שכבר הוגדרו, לבדיקה ואישור לפני שמירה. לפי הבהרת המרצה שהועברה ב־4.11.2026, פריסה ל־Production עם קישור ציבורי היא חובה; CrewAI הוא המלצה ומודל ML מאומן אינו חובה. ההבהרה הזו מנחה את גרסת ההגשה.

## מה עושים באפליקציה

1. בוחרים שבוע ומוסיפים אימון: שם, תאריך, משך מתוכנן ותרגילים מתוך התוכנית האישית.
2. אפשר להתחיל משלושה אימונים לדוגמה ולערוך אותם.
3. אחרי אימון מסמנים הושלם או דילגתי. אפשר לבטל סימון ולתקן פרטים.
4. רואים כמה אימונים הושלמו ואת היסטוריית האימונים. כל השלמה שווה 100 EXP וכל 500 EXP מעלים רמה.
5. בחשבון מחובר אפשר לבקש הצעת שיבוץ עם AI, לבדוק תאריכים ונימוקים ולאשר שמירה.
6. מתחברים לחשבון כדי לשמור בענן ולטעון את היומן גם ממכשיר אחר. אפשר גם להוריד ולשחזר גיבוי JSON.
7. פותחים ״יומן חודשי״, בוחרים יום ומוסיפים או עורכים אימון. ניתן לפתוח טיוטת אירוע ב־Google Calendar או להוריד את האימונים המתוכננים בחודש כ־ICS לייבוא ידני. כפתור חיבור נפרד מיועד לסנכרון אוטומטי עם יומן Gymmi ב־Google, וממתין להגדרת OAuth של האפליקציה. האירועים הם יום שלם. ראו [הסבר היומן](docs/CALENDAR_HE.md).

בביקור הראשון מופיעה הדרכה קצרה שאפשר לדלג עליה או לפתוח מחדש דרך ״איך מתחילים?״. ״אימון חדש״ זמין בראש המסך; במובייל יש ניווט תחתון, וחשבון ו־AI נפתחים לפי הצורך. ראו [מדריך חוויית השימוש](docs/UX_HE.md).

העיצוב המעודכן מבוסס על סקירת מסכים של Hevy, Fitbod ו־Freeletics: כרטיס לאימון הבא, רצועת ימים, טבעת התקדמות ועריכה בחלונות ממוקדים. ראו [מקורות ושיקולי עיצוב](docs/UI_RESEARCH_HE.md). הפונט העברי Heebo נשמר מקומית עם רישיון; לא מועתקים נכסים מהאפליקציות האחרות.

במצב אורח הנתונים נשמרים ב־localStorage בדפדפן. בחשבון מחובר הם נשמרים בפרויקט Supabase נפרד בשם Gymmi, בארגון שאומת במסלול Free. כל משתמש יכול לגשת רק ליומן שלו. לרענון מידע ממכשיר אחר לוחצים ״טען מחדש מהענן״; אין עדכון חי אוטומטי. היומן המקומי אינו מועלה אוטומטית ונשאר זמין אחרי יציאה מהחשבון.

**הגדרת ה־MVP:** לבקשת המשתמש ובאישורו המפורש מ־4.11.2026, ההרשמה אינה דורשת אישור מייל ומכניסה מיד לחשבון. כתובת המייל משמשת לזיהוי אך הבעלות עליה אינה מאומתת. אין כרגע שחזור סיסמה באתר ואין ספק SMTP. בדיקת הרשמה ציבורית דרך הטופס נפרדת מבדיקות הענן הוותיקות שהשתמשו בחשבונות QA שאומתו בניהול. חשבונות הבדיקה נמחקים בסיום. ראו [הסבר מלא והכנה להצגה](docs/PROJECT_EXPLAINED_HE.md).

תוכנית הדוגמה היא תבנית לארגון, ולא תוכנית שנבנתה באמצעות AI או הותאמה רפואית. אין להזין מידע רפואי רגיש ביומן הלימודי.

במסך ״רמות ודירוג שבועי״ אפשר להצטרף בחשבון מחובר באמצעות כינוי, ולעזוב בכל רגע. הטבלה מציגה את 20 המובילים לפי תאריכי האימונים שהושלמו בשבוע הנוכחי לפי שעון ישראל. הניקוד מבוסס על דיווח עצמי. מסך התוכנית והיומן החודשי סופרים את אותן השלמות. הממשק כתוב ב־HTML/CSS/JavaScript. המצגת הציבורית באנגלית; הערות לדובר ומדריך החזרה נשארים בעברית.

## קוד שאפשר להסביר

| קובץ | אחריות |
|---|---|
| docs/app/index.html | מסכי האפליקציה והטפסים |
| docs/app/style.css | עיצוב והתאמה לטלפון |
| docs/app/app.js | שמירה, אימות נתונים, עריכה, סימון השלמה וחישוב התקדמות |
| docs/app/ai.js | בקשת הצעה, בדיקת הפלט ואישור מפורש לפני שמירה |
| docs/app/ux.js | הדרכה ראשונה, קיצורי דרך ומידע על הפעולה הבאה |
| docs/app/league.js | חישוב EXP ורמות והצטרפות לדירוג |
| docs/app/calendar.js, calendar-lib.js | תצוגת חודש, בחירת יום והוספה ידנית לקלנדר |
| supabase/functions/ai-week-plan/ | פונקציית שרת: אימות משתמש, מכסה, קריאת המודל ובדיקת ההצעה |
| docs/app/cloud.js | טעינה ושמירה ב־Supabase עם בדיקת גרסה |
| docs/app/config.js | כתובת הפרויקט ומפתח publishable ציבורי בלבד |
| supabase/migrations/ | הגדרת טבלה והרשאות RLS |
| tests/browser_mvp.cjs | בדיקות משתמש בדפדפן |
| tests/cloud_mvp.cjs | בדיקות ענן ובידוד חשבונות מול שירות אמיתי |

זו אפליקציה עם HTML, CSS ו־JavaScript פשוטים, ללא framework או שלב build. GitHub Pages מגיש את הממשק ב־HTTPS ו־Supabase מספק Auth ומסד Postgres. SDK רשמי בגרסה קבועה נמצא ב־docs/app/vendor עם רישיון ופרטי מקור. עוזר השיבוץ קורא ל־OpenAI Responses API דרך Supabase Edge Function. המפתח נשמר ב־Supabase Secrets ולא בקוד הדפדפן. אין מודל חיזוי מאומן במוצר ואין יצירת תרגילים. ראו [איך עובד ה־AI](docs/AI_PLANNER_HE.md).

## הרצה מקומית

אפשר לפתוח docs/app/index.html, אך מומלץ שרת מקומי כדי לקבל סביבת דפדפן עקבית:

```powershell
python -m http.server 8520 --directory docs/app
```

פותחים http://localhost:8520. לא צריך להתקין את חבילות מעבדת ה־ML כדי להריץ את המוצר.

## בדיקות

תוצאות מצב האורח המקורי נמצאות ב־verification/production-mvp-check.json; תוצאות חיבור Supabase המקורי מופיעות ב־verification/supabase-cloud-check.json; הגדרת ההרשמה החדשה ובדיקותיה ב־verification/signup-check.json. הן מפרידות בין בדיקות מקומיות, בדיקות מול הכתובת הציבורית, ובדיקות שלא בוצעו כגון מסירת מייל. בדיקות האפליקציה הן בדיקות דפדפן ו־API; אין לבלבל בינן לבין בדיקות מעבדת הנתונים הישנה.

לבדיקות דפדפן אופציונליות בסביבת פיתוח:

```powershell
npm install --no-save playwright
npx playwright install chromium
node tests/browser_mvp.cjs http://localhost:8520/
```

לא נדרשים npm או Python כדי להשתמש באפליקציה הציבורית. בדיקות היישום אינן רצות אוטומטית ב־GitHub Actions; לחיבור הפרסום אין הרשאת workflow.

## עבודת המחקר הקודמת

קוד Python, CrewAI, נתוני Zenodo והתוצרים ב־artifacts/weekly-* נשמרים כמעבדת מחקר היסטורית. הם חוזים ביקור שבועי, ואינם משמשים את המוצר הציבורי או מוצגים כחיזוי השלמת אימון. 112 בדיקות שדווחו בפיתוח המקורי מתייחסות לאותה מעבדה. ניסוי השלמה סינתטי נשמר בנפרד ואינו רכיב חובה בהגשה או ראיה לביצועים על אנשים אמיתיים.

רישיון נתוני המחקר ההיסטוריים ב־DATA_ATTRIBUTION.md. המוצר הפעיל אינו מוריד דאטה למחקר. רק לאחר בקשת AI מפורשת נשלחים לספק הזמינות ושמות ומשך האימונים הרלוונטיים; פרטי תרגילים, מייל והיסטוריית השלמות אינם נשלחים.

## Git והגשה

הריפו הציבורי התחיל בייצוא מסומן של עבודה פרטית מוקדמת. ההיסטוריה אינה משחזרת תאריכים או שותפים. משתמשים בענפים וב־PR אמיתי, ומציינים בכנות שנעזרנו בעוזר קוד. חומרי הקורס, ההיסטוריה הפרטית והמפתחות אינם חלק מההגשה. אין כאן טענה לביקורת אנושית עצמאית, לציון מובטח או לכך שכבר נשלחה ההגשה.

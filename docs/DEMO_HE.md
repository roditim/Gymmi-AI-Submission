# הדגמה של שלוש דקות

1. פותחים את האפליקציה הציבורית: https://roditim.github.io/Gymmi-AI-Submission/app/ — ולא קישור localhost. אין צורך בהתקנה, מפתח או חשבון ChatGPT.
2. אומרים: ״Gymmi עוזר למתאמן לארגן תוכנית שבועית ולראות מה השלים.״
3. מוסיפים תוכנית דוגמה לשבוע ריק, או מוסיפים אימון ידני. מראים שם, תאריך, משך ופרטי אימון; עורכים אימון אחד.
4. מסמנים אימון של היום או של יום קודם כהושלם. רואים את מונה ההשלמות ואת ההתקדמות משתנים. אימון עתידי אינו ניתן לסימון.
5. מרעננים את הדף ומראים שהנתונים נשמרו. עוברים להיסטוריה ואז מראים גיבוי JSON.
6. אומרים: ״השמירה היא בדפדפן הזה. אין כרגע חשבונות או סנכרון בין מכשירים; אפשר להעביר גיבוי.״

## הסבר הקוד

index.html מגדיר את המסכים והטפסים. style.css קובע עיצוב רספונסיבי. app.js מגיב ללחיצות, בודק ערכים, שומר ב־localStorage ומחשב כמה מתוך האימונים השבועיים הושלמו. קודם מנסים לשמור; רק אחרי הצלחה מעדכנים את המסך. ביומן שגוי לא מחליפים מידע בשקט. טקסט משתמש מוצג עם textContent.

GitHub Pages מגיש את הקבצים באינטרנט ב־HTTPS. זהו ה־Production של ה־MVP. הנתונים המקומיים של כל מבקר אינם חלק מהריפו. מחיקת נתוני דפדפן מוחקת אותם, ולכן יש גיבוי.

## שאלות להצגה

- הערך למתאמן: תוכנית שבועית ברורה, רישום השלמה והתקדמות במקום אחד.
- מה נשמר: אימונים, פרטים וסטטוס בדפדפן; אין שרת עם משתמשים משותפים.
- מה לא להבטיח: התאמה רפואית, AI שפועל במוצר, חיזוי השלמה או סנכרון ענן.
- איפה AI: עבודת המחקר הקודמת בתיקיות Python ו־artifacts היא אופציונלית. לפי ההבהרה המעודכנת CrewAI ו־ML אינם חובה. לא מציגים את מודל הביקורים הישן כחיזוי השלמת אימון.
- סיוע בקוד: נעזרנו בעוזר קוד; צריך להבין ולהסביר את הקוד שמגישים.

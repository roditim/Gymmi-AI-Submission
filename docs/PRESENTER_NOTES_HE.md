# הערות בעברית למצגת באנגלית

עשר שקופיות בעיצוב פחם וליים, עם צילומי האתר המעודכן ונתוני דוגמה. ההסבר והדיבור יכולים להיות בעברית. תסריט מלא: [REHEARSAL_HE.md](REHEARSAL_HE.md).

## 1. Gymmi AI

פתיחה: Gymmi הוא יומן אימונים עם עוזר AI פעיל. המשתמש כותב מתי הוא פנוי, המודל מציע שיבוץ לאימונים שהוגדרו, והמשתמש מאשר לפני שמירה. אין חיזוי השלמה או יצירת תרגילים.

## 2. The workout planning journey

דוגמה פשוטה: תכננתי שלושה אימונים, השלמתי אחד והמערכת מציגה אחד מתוך שלושה. זו ספירה של נתונים שהמשתמש סימן, לא תחזית ולא המלצה רפואית. שינוי השבוע משנה את האימונים ואת ההתקדמות המוצגים. ה־AI מציע ימים, והקוד מחשב את התאריכים. זו הצעה שדורשת בדיקה ואישור, לא שינוי אוטומטי.

## 3. A focused workout dashboard

הראה את העיצוב החדש: הכרטיס הבולט הוא האימון הבא ששמור ביומן, והטבעת סופרת השלמות אמיתיות. הוספה וכניסה נפתחות בחלונות. סגירה או Escape שומרים טיוטה; שמירה מוצלחת או ביטול עריכה מנקים אותה. רצועת הימים פותחת אימון קיים או הוספה ביום ריק. במחשב ניווט צד, ובמובייל ניווט תחתון והדרכה ניתנת לדילוג. השראה חזותית בלבד: מקורות ב־docs/UI_RESEARCH_HE.md. אין כאן מחקר משתמשים או XP.

## 4. Browser, Supabase and OpenAI

הדפדפן פונה ל־Supabase Edge Function עם Session. השרת מאמת את המשתמש וקורא את היומן בהרשאותיו. ל־OpenAI נשלחים רק הזמינות, שמות ומשך האימונים, והימים המותרים. המפתח נשאר ב־Secrets. המודל מחזיר יום בשבוע, הקוד ממיר לתאריך ומאמת. רק אישור המשתמש מפעיל שמירה רגילה עם revision.

## 5. The user approves every AI change

צילום ההצעה מגיע מבדיקת מודל אמיתית עם נתוני QA לדוגמה. לא נשמר שינוי עד האישור. הפלט מוגבל למזהי אימונים ולימים מותרים. שינוי יומן או זמינות מבטל הצעה קודמת. הניסוי תפס פעם טעות ביום; העברנו את המרת ימי השבוע לתאריכים לקוד. עדיין ייתכנו טעויות בפירוש הבקשה, ולכן נדרשת בדיקה אנושית.

## 6. Monthly calendar and manual export

זהו צילום אמיתי של האתר עם שלושה אימוני אורח לדוגמה, ללא חשבון אישי. calendar.js מצייר את אותו state.workouts של השבוע. calendar-lib.js מחשב ימים ומייצר ICS וקישור לטיוטת Google. הייצוא כולל רק אימונים מתוכננים בחודש הנבחר. שם, תאריך ומשך בלבד; פרטי התרגילים אינם מועברים. האירוע יום שלם כי אין שעת התחלה במוצר. המשתמש שומר ידנית ב־Google; Gymmi אינה יודעת אם שמר. שינוי ב־Gymmi לא משנה עותק חיצוני, וייבוא חוזר עלול ליצור כפילויות.

## 7. Verification results

אלה תוצאות מתועדות מהריצה האחרונה של העיצוב: 6 קבוצות עיצוב ו־8 קבוצות הדרכה/ניווט על האתר הציבורי בחמישה רוחבים, ועוד 6 קבוצות הרשמה ושמירה ציבוריות ב־390x844. זו הדמיית גודל Chrome, לא מכשיר פיזי. 8 קבוצות AI הורצו מקומית מול שירותי השרת, ובהן שתי קריאות מודל אמיתיות בעברית ובאנגלית; מקרים לא תקינים וישנים נבדקו עם הדמיות מסומנות. גם בדיקות כללים קודמות עברו: 9 ל־AI ו־7 ליומן. אין לחבר את הקבוצות למספר משתמשים או לציון דיוק. הרצות ממחשב הפיתוח, לא CI. מקור: verification/ui-redesign-check.json.

## 8. Git workflow and public deployment

Git היא מערכת ניהול גרסאות, GitHub הוא האתר שמחזיק את הריפו ו־PR, ו־Cursor הוא עורך הקוד. branch מאפשר לפתח שינוי בנפרד מ־main. commit מתעד קבוצת שינויים. push מעלה את ההיסטוריה ל־GitHub. PR מציג הבדלים ותיאור; merge מכניס ל־main. PR אמיתי אינו הוכחה שמפתח אחר עשה סקירה. המיזוג אצלנו מפעיל פרסום GitHub Pages, אבל Edge Function פורסמה בנפרד ל־Supabase. בדיקות המוצר בוצעו ידנית ממחשב הפיתוח, לא ב־CI אוטומטי. דוגמאות: https://github.com/roditim/Gymmi-AI-Submission/pull/9 ו־https://github.com/roditim/Gymmi-AI-Submission/pull/11. אין סודות בריפו. העיצוב החדש נכנס ב־PR #16: https://github.com/roditim/Gymmi-AI-Submission/pull/16. Cursor הוא עורך בלבד; אין חיבור נוסף שחייבים להפעיל כדי להציג את ההיסטוריה. אפשר לפתוח את אותה תיקייה ב־Cursor ולראות Git.

## 9. Live demo

הכן חשבון הדגמה מראש. לחץ כניסה / הרשמה ואז אימון חדש. הוסף אימון להיום, שמור וסמן הושלם. הראה את הטבעת ורענן. עבור לשבוע הבא, הוסף שני אימונים של 30 דקות, פתח עזרה בשיבוץ עם AI וכתוב: פנוי רק ברביעי ובשישי, עד 30 דקות בכל יום. בדוק תאריכים ונימוקים, הראה שהכרטיסים לא השתנו ואז אשר את השיבוץ ואת הודעת האישור. עבור ליומן החודשי ובחר את החודש הנכון. לסיום הראה PR #16. ICS הוא הרחבה אם נשאר זמן. יש 3 ניסיונות ביום UTC לחשבון ו־100 לפרויקט כולל כשלים, ללא איפוס אוטומטי. אם הבקשה נכשלת, הראה צילום קודם והצהר שהוא צילום, ללא המצאת ריצה חיה.

## 10. Scope and current limits

ההבהרה האחרונה של יונתן קובעת: קישור ציבורי חובה; CrewAI ו־ML מאומן אינם חובה. אין להבטיח ציון או אישור למימוש המסוים. אין חיזוי השלמת אימון או יצירת תרגילים. אין OAuth ל־Google ואין סנכרון דו־כיווני. המשתמש אישר הרשמה בלי אימות מייל ל־MVP הלימודי; אין שחזור סיסמה. Supabase נבנה במסלול Free; שימוש ב־OpenAI מחויב בנפרד, עם 3 ניסיונות ביום UTC לחשבון ו־100 לפרויקט כולל כשלים. נעזרתי בעוזר קוד ואני אחראי להבין ולהסביר את מה שאני מגיש. ההיקף תואם את ההבהרה האחרונה שנמסרה, אך לא התקבל אישור נפרד של המרצה לכל פרט במימוש הסופי.

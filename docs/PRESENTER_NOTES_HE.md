# הערות בעברית למצגת באנגלית

המצגת כוללת עשר שקופיות. אפשר להקדיש כשתי דקות לשקופיות ולשלוש עד חמש דקות להדגמה. הסבר מלא: [REHEARSAL_HE.md](REHEARSAL_HE.md).

## 1. Gymmi AI

פתיחה: Gymmi הוא יומן אימונים עם עוזר AI פעיל. המשתמש כותב מתי הוא פנוי, המודל מציע שיבוץ לאימונים שהוגדרו, והמשתמש מאשר לפני שמירה. אין חיזוי השלמה או יצירת תרגילים.

## 2. The workout planning journey

דוגמה פשוטה: תכננתי שלושה אימונים, השלמתי אחד והמערכת מציגה אחד מתוך שלושה. זו ספירה של נתונים שהמשתמש סימן, לא תחזית ולא המלצה רפואית. שינוי השבוע משנה את האימונים ואת ההתקדמות המוצגים. ה־AI מציע ימים, והקוד מחשב את התאריכים. זו הצעה שדורשת בדיקה ואישור, לא שינוי אוטומטי.

## 3. The MVP features

המשתמש הוא מתאמן. אפשר לתכנן אימונים ולראות אותם בשתי תצוגות: שבוע וחודש. אלה אותם נתונים, לא שתי רשימות שונות. סטטוס השלמה והיסטוריה מבוססים על סימון המשתמש. עיצוב ה־RPG הוא חזותי בלבד, ללא XP או דמות.

## 4. Browser, Supabase and OpenAI

הדפדפן פונה ל־Supabase Edge Function עם Session. השרת מאמת את המשתמש וקורא את היומן בהרשאותיו. ל־OpenAI נשלחים רק הזמינות, שמות ומשך האימונים, והימים המותרים. המפתח נשאר ב־Secrets. המודל מחזיר יום בשבוע, הקוד ממיר לתאריך ומאמת. רק אישור המשתמש מפעיל שמירה רגילה עם revision.

## 5. The user approves every AI change

צילום ההצעה מגיע מבדיקת מודל אמיתית עם נתוני QA לדוגמה. לא נשמר שינוי עד האישור. הפלט מוגבל למזהי אימונים ולימים מותרים. שינוי יומן או זמינות מבטל הצעה קודמת. הניסוי תפס פעם טעות ביום; העברנו את המרת ימי השבוע לתאריכים לקוד. עדיין ייתכנו טעויות בפירוש הבקשה, ולכן נדרשת בדיקה אנושית.

## 6. Monthly calendar and manual export

זהו צילום אמיתי של האתר עם שלושה אימוני אורח לדוגמה, ללא חשבון אישי. calendar.js מצייר את אותו state.workouts של השבוע. calendar-lib.js מחשב ימים ומייצר ICS וקישור לטיוטת Google. הייצוא כולל רק אימונים מתוכננים בחודש הנבחר. שם, תאריך ומשך בלבד; פרטי התרגילים אינם מועברים. האירוע יום שלם כי אין שעת התחלה במוצר. המשתמש שומר ידנית ב־Google; Gymmi אינה יודעת אם שמר. שינוי ב־Gymmi לא משנה עותק חיצוני, וייבוא חוזר עלול ליצור כפילויות.

## 7. Verification results

תוצאות מתועדות ולא בדיקות חדשות של מודל בשקופית: 24 קבוצות יומן/ענן/הרשמה; 8 קבוצות AI עם שתי קריאות מודל אמיתיות בכל ריצה ושאר תרחישים עם הדמיות מסומנות; 9 בדיקות כללי AI. ליומן החודשי נוספו 7 קבוצות דפדפן ו־7 בדיקות לוגיקת תאריכים/ייצוא. Google מדומה בבדיקה ולא נוצר אירוע אמיתי. אין CI לבדיקות ב־GitHub; הריצות בוצעו ממחשב הפיתוח מול האתר והשירותים. מקורות: verification/ai-planner-check.json ו־verification/calendar-check.json.

## 8. Git workflow and public deployment

Git היא מערכת ניהול גרסאות, GitHub הוא האתר שמחזיק את הריפו ו־PR, ו־Cursor הוא עורך הקוד. branch מאפשר לפתח שינוי בנפרד מ־main. commit מתעד קבוצת שינויים. push מעלה את ההיסטוריה ל־GitHub. PR מציג הבדלים ותיאור; merge מכניס ל־main. PR אמיתי אינו הוכחה שמפתח אחר עשה סקירה. המיזוג אצלנו מפעיל פרסום GitHub Pages, אבל Edge Function פורסמה בנפרד ל־Supabase. בדיקות המוצר בוצעו ידנית ממחשב הפיתוח, לא ב־CI אוטומטי. דוגמאות: https://github.com/roditim/Gymmi-AI-Submission/pull/9 ו־https://github.com/roditim/Gymmi-AI-Submission/pull/11. אין סודות בריפו.

## 9. Live demo

הדגמה: חשבון מוכן מראש, אימון להיום לסימון השלמה. בשבוע הבא הוסף שני אימונים של 30 דקות, כתוב שפנויים רק ברביעי ובשישי ובקש הצעה. הראה שלא נשמר דבר לפני האישור. אשר ורענן; עבור ליומן החודשי ובחר את החודש והיום המתאימים. הראה ייצוא ICS בלי לחבר חשבון Google. לבסוף פתח PR ממוזג בריפו. אם המודל נכשל, הראה את הודעת הכשל ואת הצילום מבדיקה קודמת, עם הסבר מפורש שזה צילום קודם. שמור ניסיון אחד להצגה: 3 ביום UTC לחשבון ו־100 לכל הפרויקט.

## 10. Scope and current limits

ההבהרה האחרונה של יונתן קובעת: קישור ציבורי חובה; CrewAI ו־ML מאומן אינם חובה. אין להבטיח ציון או אישור למימוש המסוים. אין חיזוי השלמת אימון או יצירת תרגילים. אין OAuth ל־Google ואין סנכרון דו־כיווני. המשתמש אישר הרשמה בלי אימות מייל ל־MVP הלימודי; אין שחזור סיסמה. Supabase נבנה במסלול Free; שימוש ב־OpenAI מחויב בנפרד, עם 3 ניסיונות ביום UTC לחשבון ו־100 לפרויקט כולל כשלים. נעזרתי בעוזר קוד ואני אחראי להבין ולהסביר את מה שאני מגיש.

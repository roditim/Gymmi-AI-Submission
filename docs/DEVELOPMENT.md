# Development

Onboarding and shortcuts live in docs/app/ux.js. They use the separate optional gymmi-onboarding-v1 preference, never replace the journal or upload guest workouts. The initial tour is inline and skippable. The redesigned shell uses desktop side navigation and mobile bottom navigation, native dialogs for workout/account forms, a seven-day strip and a progress ring calculated from journal completion. Escape/close retain an unsaved draft; successful save or explicit cancel resets it. Main action IDs and data protections are preserved. Less frequent workout actions are in an explicit details menu. Tests use ui_helpers.cjs to open dialogs/menus through actual clicks, not bypass the UI. Heebo is bundled under fonts/ with its OFL license and source hash; competitor screenshots remain outside the repo. Research and design decisions are documented in UI_RESEARCH_HE.md. Tests describe Chrome viewport emulation, not physical-device testing. That UI redesign did not change the journal schema.

The production application is docs/app: buildless HTML, CSS and JavaScript. Serve it with python -m http.server 8520 --directory docs/app, or any static HTTP server. The GitHub Pages source is main:/docs, so the app is at /Gymmi-AI-Submission/app/ and the presentation is at the repository Pages root.

The RPG-inspired theme uses CSS, a native SVG emblem and status badges. Personal EXP is derived from the existing journal in league.js. The owner-only league_members table stores opt-in nicknames. The weekly_league RPC returns the top 20 from completed journal entries dated in the current Israel week, with only rank, alias, score and an is_you marker. A private SQL function reads the aggregate and the public wrapper runs with invoker privileges. Exiting deletes the membership and retains personal EXP. Preserve IDs and accessible action labels used by the browser tests. The English presentation source is docs/presentation.json; public HTML is docs/index.html. The desktop, league, calendar and AI screenshots in docs/assets are actual captures with sample guest/QA data. The AI capture comes from a regression run with sample data. The public deck includes its visible slide content.

Open Gymmi.code-workspace in Cursor. Use a branch and real PR. Test guest behavior with tests/browser_mvp.cjs and cloud behavior with tests/cloud_mvp.cjs. Playwright is an optional development tool. Visitors do not need a Python installation or admin credentials. The pinned, vendored Supabase SDK is a runtime dependency; its source/version/integrity are documented under docs/app/vendor.

The separate Gymmi Supabase project is yvzfkaswrohpniheubpn, eu-central-1. Its organization was confirmed Free before provisioning. config.js contains only the intended public publishable key. Never add a service key, management token or database password to the browser/repo. The schema is captured in supabase/migrations. It was applied using CLI db query against the new project; no local Docker database or db-push migration replay was run. On another empty project apply that SQL once, with appropriate operator access. Auth uses the production app URL as its site URL; password minimum is 10. The user explicitly approved email confirmation being disabled for the educational MVP on 2026-11-04. The Supabase Auth setting is mailer_autoconfirm=true. Signup returns an immediate session; email ownership is not verified. No custom SMTP or password recovery UI exists. tests/signup_mvp.cjs exercises actual public signup without admin confirmation; its admin key is used only to delete its disposable account.

One workout_journals row holds each user's JSON diary and revision. RLS enforces auth.uid() = user_id for select/insert/update; anonymous roles have no table access. There is no client DELETE grant. Reset writes an empty array. Cloud writes use revision filters and update the UI only after acknowledgment. Guest imports require explicit confirmation and never happen on sign-in. Refresh or Reload from cloud obtains changes from another device; there is no realtime subscription or offline cloud queue.

Run cloud QA only against the intended test project, with a service key supplied in the process environment as GYMMI_TEST_SERVICE_KEY. The test creates uniquely named disposable QA accounts through the Auth admin endpoint, tests ordinary user sessions and RLS, and deletes only those accounts in finally. It never tests mail delivery or accepts a stored real-user session. Do not put that key into any tracked file, terminal output or screenshot.

The AI scheduler lives in docs/app/ai.js and supabase/functions/ai-week-plan. It calls gpt-5.4-mini through the Responses API with strict JSON schema and store:false. User JWT verification remains enabled at the gateway; the function also verifies the caller with Auth and reads the journal under the user's token. Only preference text, titles, durations and allowed dates reach OpenAI. Exercise details and history stay out of the request. No prompts or provider responses are logged by our code. store:false is not a claim of zero provider retention.

The server secret OPENAI_API_KEY is configured through Supabase Secrets. Never place it in config.js. Supabase stays Free; OpenAI API usage has separate provider billing. claim_ai_request is a service-role-only RPC with atomic counters: 3 attempts per user per UTC day and 100 attempts total for this demo project, including failed provider calls. The global budget never resets automatically. The two quota tables have RLS enabled and no browser grants. An operator must review/reset any exhausted project budget manually. New migration SQL was applied using db query, not a local Docker replay.

Deploy with the installed CLI using functions deploy ai-week-plan --project-ref <Gymmi-ref> --use-api after reviewing --help. Production CORS allows roditim.github.io, plus localhost/127.0.0.1 port 8530 for development. For local AI testing, serve docs/app on port 8530; the earlier 8520 example supports the journal but is not an allowed AI origin. There is no wildcard origin. The function returns proposals and never updates workout_journals. User approval goes through the existing revision-protected save. Unit tests: node --test tests/ai_planner.test.mjs. tests/ai_mvp.cjs uses two real model calls plus labelled mocked invalid/stale outputs and disposable QA accounts. Test quotas with rollback rather than changing the production counter permanently.

Production verification is recorded in verification/ai-planner-check.json: 8 AI browser scenario groups, including two real model calls in English and Hebrew, plus 24 existing guest/cloud/signup groups on the public URL. Nine pure validator tests passed locally. These runs use a local runner against deployed services, not hosted CI. The receipt records the tested runtime commit and deployment run; later documentation-only commits do not change that runtime.

The monthly calendar uses calendar.js for rendering and calendar-lib.js for pure month/ICS/Google-draft helpers. It reads the same state.workouts and reuses editWorkout/mark/save. There are no new database fields, dependencies or Google OAuth credentials. The user explicitly deferred connecting a personal Google account. Google drafts require manual confirmation and save in Google; no account connection or automatic synchronization exists. ICS is a snapshot of planned workouts in the displayed month, with stable scoped UIDs and RFC 5545 text escaping/UTF-8 line folding. All events are all-day, with exclusive next-day end dates. Neither export includes exercise details. Re-imports may duplicate events; editing/deleting the Gymmi workout does not change an already imported event. Unit checks: node --test tests/calendar.test.cjs. Browser checks: node tests/calendar_mvp.cjs <URL>; Google opening is intercepted and no real calendar event is created.
